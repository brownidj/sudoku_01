# Testing and Unlocking the Full Version with Xcode

This guide explains how to build and launch the Flutter iOS app in the iOS Simulator using Xcode so that the local `Premium.storekit` configuration is active and the Full version can be purchased for testing.

## Why the app must be launched from Xcode

The iOS project contains a local StoreKit configuration file:

```text
Premium.storekit
```

The `Runner` scheme is configured to use this file. However, the local StoreKit test environment may not be applied when the app is launched from PyCharm or with `flutter run`.

When the local StoreKit configuration is active:

- no real purchase is made;
- no real payment method is used;
- an Apple Account or Sandbox account should not be required;
- the purchase is handled locally by Xcode;
- test transactions can be inspected and removed in Xcode.

If the purchase dialog asks for an Apple Account email address and password, the app is probably using the App Store sandbox rather than the local `Premium.storekit` configuration.

---

## 1. Stop the app in PyCharm

Stop the current Flutter run before launching the app from Xcode.

This prevents PyCharm and Xcode from attempting to control the same app or Simulator session.

---

## 2. Open the Xcode workspace

From the root directory of the Flutter project, open Terminal and run:

```zsh
open ios/Runner.xcworkspace
```

Open:

```text
Runner.xcworkspace
```

Do **not** open:

```text
Runner.xcodeproj
```

The workspace includes the Flutter iOS dependencies generated by `flutter pub get`.

---

## 3. Select the Runner scheme and Simulator

At the top of Xcode:

1. Select the **Runner** scheme.
2. Select the required Simulator, such as:

```text
iPhone 17 Pro Max
```

Do not select **Any iOS Device** when you intend to run the app in the Simulator.

---

## 4. Confirm the StoreKit configuration

In Xcode:

1. Select **Product → Scheme → Edit Scheme…**
2. Select **Run** in the left-hand column.
3. Open the **Options** tab.
4. Find **StoreKit Configuration**.
5. Select:

```text
Premium.storekit
```

6. Close the scheme editor.

This is the critical step. The file merely existing in the project is not enough; it must be selected for the active Run scheme.

---

## 5. Build and launch the app

Use either:

```text
Product → Run
```

or press:

```text
⌘R
```

Xcode will:

1. build the Flutter iOS app;
2. start the selected Simulator if necessary;
3. install the app;
4. launch it;
5. attach the debugger;
6. activate the local StoreKit test environment.

---

## 6. Purchase the Full version

In the running app:

1. Open the side drawer.
2. Tap **Unlock Full Version**.
3. Confirm the local test purchase in the StoreKit purchase sheet.

With `Premium.storekit` active, the purchase should complete locally. It should not require a real Apple Account sign-in or charge any money.

After the transaction completes, the app should change from the Free version to the Full version and unlock the associated features.

---

## 7. Inspect or reset the test transaction

While the app is running from Xcode, open:

```text
Debug → StoreKit → Manage Transactions
```

The StoreKit Transaction Manager can be used to:

- confirm that the purchase was recorded;
- inspect the transaction;
- delete the transaction;
- test purchasing again;
- simulate refunds or other transaction states where supported.

To return the app to an unpurchased state, delete the local transaction and relaunch the app. The app may also have its own developer-only reset mechanism.

---

## 8. Recording the purchase with OBS

OBS can continue capturing the Simulator while Xcode launches and controls the app.

A suitable OBS setup is:

- **macOS Screen Capture**
  - Method: **Application Capture**
  - Application: **Simulator**
- Capture the Simulator audio using OBS's native macOS application-audio capture where available.
- Remove or mute the BlackHole source if OBS is already capturing the Simulator audio directly, to avoid duplicate audio.

Start the OBS recording before opening the app drawer and selecting **Unlock Full Version**.

---

## Troubleshooting

### The purchase dialog requests an email address and password

This usually means the local StoreKit configuration is not active.

Check that:

- the app was launched with Xcode rather than PyCharm;
- `Runner.xcworkspace` was opened;
- the active scheme is **Runner**;
- **Run → Options → StoreKit Configuration** is set to `Premium.storekit`;
- the app was rebuilt and relaunched with `⌘R`.

### `Premium.storekit` is not available in the scheme

Confirm that the file has been added to the Xcode project. If necessary, drag it into the Runner project navigator and ensure it is included in the project.

### Flutter-generated files are missing

From the Flutter project root, run:

```zsh
flutter pub get
```

Then reopen the workspace:

```zsh
open ios/Runner.xcworkspace
```

### Flutter-generated package files are stale

From the Flutter project root, run:

```zsh
flutter pub get
open ios/Runner.xcworkspace
```

### The purchase succeeds but the Full version does not unlock

Check:

- that the product identifier in `Premium.storekit` exactly matches the identifier used by the app;
- that the app listens for and verifies the completed StoreKit transaction;
- that the entitlement state is refreshed after purchase;
- that the transaction is visible under **Debug → StoreKit → Manage Transactions**.

## Quick procedure

```text
Stop the app in PyCharm
→ open ios/Runner.xcworkspace
→ select Runner
→ select the iPhone Simulator
→ Product → Scheme → Edit Scheme
→ Run → Options
→ select Premium.storekit
→ press ⌘R
→ open the app drawer
→ tap Unlock Full Version
→ confirm the local purchase
→ inspect it under Debug → StoreKit → Manage Transactions
```
